深度分析：架构如何决定速度、弱相互作用与下游性质

本页把“底层结构”与“可观测表现”连起来看。架构事实来自各模型源码（见各模型页面）；数字来自 Matbench Discovery（MBD）与 MLIP Arena 仓库里的原始结果文件（固定 commit，见 基准数据 页）。所有图表都由浏览器从这些数据实时绘制。

结论摘要

⚡ 速度

  • 单步开销 ≈ 原子数 × 邻居数 × 层数 × 每条边的运算量 ×（1 + 反传）。邻居数 ∝ rc3，所以截断半径和层数是最大的杠杆，其次才是“用不用球谐”。
  • 同一平台、同一 384 原子体系：直接力的 Orb ≈ 55 步/秒，保守力的 MACE / MatterSim ≈ 32–34，SevenNet ≈ 24，EquiformerV2 ≈ 9，eSCN ≈ 4.6，CHGNet ≈ 3，M3GNet ≈ 1.6。
  • 实现与架构同样重要：MatterSim-v1 本质上是放大的 M3GNet，但借助 GPU 建图与编译比 matgl 版 M3GNet 快约 20 倍。

🧲 弱相互作用 / 长程

  • 缺口有两层：数据层（PBE 训练集本身就没有色散）和架构层（截断 + 有限感受野丢掉 1/r 静电与 r−6 尾巴）。前者往往更致命。
  • 统计见下文能力矩阵：绝大多数完整势没有任何显式静电；内置“电荷 + 静电 + 色散”的只有 PhysNet、SpookyNet、AIMNet2、SO3LR、BAMBOO、FeNNix 等分子 / 电解质路线。
  • 消息传递把名义视野放大到 T·rc（十几到上百 Å），但并不是真正的长程：相距超过 rc 的两个分子之间没有边，相互作用严格为 0。

🔬 下游性质

  • MBD 中 4 个直接力条目的热导率误差 κSRME 全部在 1.67 以上（0 最好、2 最差），最好的保守力模型已低于 0.1：二阶性质要求力是能量的精确梯度。
  • 对称性是否“精确”直接写在弛豫结果里：严格容差下，无约束（Orb、PET）与直接力模型只有约 13–14% 的结构保持原有对称性，精确 O(3) 等变的保守力模型约 70%。
  • 同一架构从 MPtrj 换到 MPtrj + OMat24 + sAlex，F1 普遍提升 0.07–0.19；只用 MPtrj 时不同架构之间也能差 0.2 以上——数据与架构都关键。

🧭 选型一句话

  • 超大规模、固定体系的 MD：严格局域 + 可训练的小模型（Allegro、NEP、DeePMD、ACE/MTP），或用基础模型生成数据后蒸馏。
  • 通用材料筛选 / 弛豫 / 声子：精确等变 + 保守力 + 大数据（OAM / OMat 系列）。
  • 分子、溶液、电解质、界面：选内置电荷与色散的架构，或给基础模型加 D3/D4 与 LES 一类长程模块，并检查训练数据的泛函。

A. 速度：时间花在哪里？

A1. 代价从哪里来

把一次“能量 + 力”的计算拆开，大致是：

N：原子数；T：消息传递层数（描述符/线性模型可视为 1）；M̄：平均邻居数，ρ 是原子数密度（固体约 0.05–0.1 Å−3）：rc = 5 Å 时 M̄ ≈ 26–52，6 Å 时 ≈ 45–90； cedge：每条边上的运算量，由“几何编码 + 消息函数”决定，是各家族的根本差别；γgrad ≈ 1–2：自动微分求力的额外开销；tgraph：建邻居表（在 CPU 上用 Python 建图常常比网络本身还慢）；t0：固定开销（内核启动、Python 调度）。

家族每条边上的核心运算代价随什么增长速度直觉
线性 / 核方法多体基函数求值 + 线性组合（ACE、MTP、SNAP、UF3 样条）基函数个数、多体阶；无层数最快，CPU 上也能跑百万原子；GAP 的核回归随稀疏点数增长
描述符 + NN对称函数 / 嵌入矩阵 → 每元素小 MLP描述符维度；DeePMD 的嵌入网络作用在每条边上很快，严格局域，NEP（GPUMD）是速度标杆之一
不变 MPNN标量滤波 × 特征（门控 MLP、矩阵乘）通道数²；若有三体“线图”，三元组数 ∝ N·M3b2本身轻量，但三体线图与 CPU 建图会拖慢（M3GNet、CHGNet）
笛卡尔等变矢量 / 张量的点积、外积、矩阵乘张量阶数 L（分量 3L），通常 L ≤ 2–3中等偏快：避开 CG 系数，GPU 友好
球谐等变CG 张量积 / SO(2) 卷积 / 注意力朴素 CG 张量积 ∝ L6；eSCN 的 SO(2) 技巧降到 ∝ L3；再乘通道数与层数lmax ≤ 2–3 的 MACE、NequIP、SevenNet 中等；lmax = 4–6 + 注意力（EquiformerV2、eSCN）明显更慢
无约束普通边 / 节点 MLP、注意力边数 × 宽度²；邻居上限直接截断边数最 GPU 友好；Orb 的直接力版本是基准里最快的通用模型

读图 ① 前三档都没有高阶球谐：Orb 是纯 MLP + 直接力；MACE 用 lmax 较低的对称收缩；MatterSim 是不变网络。 ② EquiformerV2 / eSCN 即使是直接力（省了反传）也只有 4.6–9 步/秒：OC20 版本用高 lmax（4–6）、深层堆叠的 SO(2) 卷积（EquiformerV2 还有注意力），每条边的代价太大。 ③ CHGNet 和 M3GNet 参数最少（≈0.2–0.4 M），却最慢：三体线图 + CPU / Python 建图 + eager PyTorch。参数量 ≠ 速度。 ④ MatterSim-v1 与 M3GNet 架构同源，速度却相差约 20 倍——工程实现（GPU 建图、编译、批处理）可以抵消一个数量级。

A3. 随体系增大的标度

Arena 的升温稳定性测试覆盖了 75–1480 原子的体系。对每个模型拟合 步/秒 ≈ a·N−n（与 Arena 自身的拟合方式相同）：n 接近 1 说明计算量已经随原子数线性增长（GPU 已“喂饱”）；n 远小于 1 说明在这个尺寸范围内固定开销占主导，模型还有余量。

“完整跑完”= 轨迹达到目标时长的 98% 以上。双对数坐标；点为单条轨迹，线为幂律拟合。

A5. 并行扩展与工程优化

局域性决定多 GPU 扩展

空间分解并行时，每块子区域要额外携带一层“幽灵原子”。严格局域模型只需厚度 rc；T 层消息传递要么携带厚度 T·rc 的幽灵层（大量重复计算），要么每层都通信一次。

这正是 Allegro（严格局域的等变模型）、DeePMD、NEP、ACE 在亿级原子 MD 上的结构性优势；消息传递模型（MACE、SevenNet 等）需要专门的逐层通信实现才能高效扩展。

同一架构，工程可以差一个数量级

  • 融合的等变内核：NVIDIA cuEquivariance、OpenEquivariance、FlashTP 等把 CG 张量积 / 对称收缩做成单个 GPU 内核（见 cuEquivariance）。
  • 编译：torch.compile、AOTInductor、TorchScript / JAX 导出，去掉 Python 调度开销。
  • GPU 上建邻居表（替代 pymatgen / ASE 的 CPU 建图），对小体系 MD 尤其关键。
  • 低精度：TF32 / FP32 通常足够跑 MD，但严格的对称性与二阶导数（声子）对数值精度更敏感。
  • LAMMPS ML-IAP / Kokkos、GPUMD、TorchSim 等 MD 引擎的原生接口避免了 ASE 的逐步 Python 往返。

B2. 两个层面的缺口：数据与架构

① 数据层：PBE 里本来就没有色散

MPtrj、Alexandria、OMat24 这些材料基础模型的主力训练集都是 PBE(+U)。PBE 几乎不描述色散，所以模型学到的是“没有 vdW 的世界”：石墨层间几乎不结合、分子晶体密度偏低、物理吸附能偏弱。这个缺口与架构无关——再强的网络也学不到数据里没有的物理。

② 架构层：截断 + 有限感受野

B7. 实践建议

避免重复计算色散

  • 训练数据是 PBE(+U)（MPtrj / Alex / OMat）→ 叠加 PBE 参数的 D3(BJ)。
  • 训练数据已含色散（UMA 的 omc / odac / omol 任务、orb-d3 系列、SPICE 训练的 MACE-OFF）→ 不要再加 D3。
  • r²SCAN 训练的模型 → 用 r²SCAN 对应的 D3/D4 参数，而不是 PBE 参数。

公开基准几乎不测弱相互作用

MBD 的任务（稳定性、弛豫、声子、双原子、MD）都在 PBE 无色散的框架内；双原子曲线也只有同核体系。若你的问题依赖弱相互作用，请自行测试，例如：分子晶体晶格能（X23）、非共价二聚体结合曲线（S66×8）、层状材料层间结合与层间距、水团簇与液态水密度、离子液体 / 电解质的密度与电导、带电表面的功函数或界面电势降。

C. 下游性质：架构细节如何显形

C1. 保守力 vs 直接力：声子与热导

热导率 κ 需要准确的二阶（甚至三阶）力常数，也就是力对坐标的导数。只有当力是能量的精确梯度时，这些导数才自洽。MBD 的 targets 字段标明了模型如何得到力：EFS_G = 能量求导（保守），EFS_D = 直接预测。

κSRME：103 个晶体的晶格热导率对称相对平均误差（0 最好，2 最差）。F1：稳定性发现分类分数。EFSH_G 表示训练中还加入了 Hessian / 声子信息。

C3. 对称性保持：等变是否“精确”决定弛豫结果

MBD 的结构弛豫任务统计弛豫后空间群是否与 DFT 一致（这里取最严格的 symprec = 10−5）。如果模型的力在对称位置上不严格为零（等变性不精确），弛豫就会把晶体“推歪”，对称性下降。结果几乎按架构类别整齐分层：

解读 无结构等变（Orb、PET：靠数据增强“学”对称性）与直接预测力的条目全部落在 13–14%； 非严格旋转不变的 AlphaNet（标架中向量长度用 L1 范数）同样如此； S² 网格非线性（eSEN、EquiformerV3、DPA-4 等：SO(2) 卷积精确，但网格上的逐点非线性只在网格分辨率内近似等变）大多在 25–43%（DPA-4.1c 例外，约 71%）； 只保证 SO(3)、不含宇称的 SevenNet-0 / l3i5 与 HIENet 约 44–45%，而加入宇称的 SevenNet-MF-ompa / Omni 升到约 71%； 精确 O(3) 等变或不变 + 保守力的 MACE、NequIP、Allegro、GRACE、DPA-3、MatterSim 等多在 68–74%。 容差放宽时差距会缩小，数值精度（FP32 / FP64）也有影响；但这清楚说明：“近似等变”在需要严格对称性的任务里会显形。

C4. 短程与曲线光滑性：双原子势能曲线

MBD 扫描同核双原子从极近到解离的能量曲线。理想曲线只有一个极小值：力的符号翻转次数（force flips）≈ 1，曲折度（tortuosity）= 1；“能量跳变”（energy jump，单位 eV）衡量曲线上非物理的振荡和跳变。训练数据几乎不含 < 1 Å 的构型，所以这里主要考验架构的短程先验（如 ZBL 排斥）与光滑性（包络函数、保守力）。

点击表头排序。黄色高亮：能量跳变 > 10 eV，说明在极短距离处曲线出现严重的非物理行为（高温高压 MD、辐照碰撞中会有风险）。

MLIP Arena：极端条件下能否跑完

升温：NVT，10 ps 内 300 → 3000 K；加压：NPT，10 ps 内 300 → 3000 K 且 0 → 500 GPa。“平均完成度”是轨迹在崩溃前跑完的比例的平均值。

读图 RDF / ADF 误差与 F1 高度相关（见左表下方的相关系数），数据规模与架构精度的提升会直接传导到 MD 结构性质。直接力条目表现分化：eqv2-m 的 RDF 误差与同等 F1 的保守模型相当，orb-v2 则明显偏大（约 5.1，而 F1 相近的保守模型约 3.6）。 Arena 加压测试极为苛刻（500 GPa），多数模型没能完整跑完：高压把原子间距压进训练数据很少覆盖的短程区域，这与 C4 的短程行为是同一类问题。

C6. 反应性：氢气燃烧

H2 + O2 在 3000 K 下应该反应生成水；“水产率”= 轨迹最后一帧中识别出的水分子数 / 128（用 ASE 的自然共价半径判断成键）。

  • MACE（两个版本）、MatterSim、SevenNet 都完整跑完且产率 0.71–0.89。
  • Orb / Orb v2 速度最快、也完整跑完，但最后一帧没有识别出任何水分子——数据就是这样，原因需看轨迹（可能与远离平衡的反应构型在训练数据中稀少、直接力等有关），这里不过度解读。
  • CHGNet、EquiformerV2、eSCN、M3GNet 没有跑完，它们的“产率”是中途某一帧的值，不能与其他模型直接比较。
